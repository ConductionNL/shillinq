(c) The seven canonical kerntaken (ruimte, mobiliteit, water, milieu, cultuur, economie, bestuur) ARE already seeded on `development` as `BBVProgramma` records carrying `bbvVariant: provincie` in `lib/Settings/register.d/bookkeeping-provincies-bbv-variant.json` (the T3 sibling's fragment, L181-269) — but the umbrella's anticipated standalone seed file `lib/Settings/seeds/bbv-provincies-kerntaken-2026.json` does NOT exist as a separate JSON document; the inline `objects` block on the T3 fragment is the canonical seed shape. The umbrella's Task 9 seed-file proposal is therefore a CARRIER for the same kerntaken set already on dev (the design shift is from "separate seed file imported by repair step" to "inline objects array auto-merged via ADR-037 fragment loader") and the deduplication note is recorded here. (d) The `bbvVariant` enum on the canonical `Account` (L1110-1121) AND `BBVProgramma` (L2462-2473) schemas in `lib/Settings/shillinq_register.json` ALREADY carries `'provincie'` as a value alongside `gemeente | waterschap` — REQ-PRB-001's enum-extension requirement is satisfied on dev. (e) The `programmaStructure` discriminator on `BBVProgramma` in `lib/Settings/shillinq_register.json` L2452-2461 currently carries `[taakveld, kostentoedeling]` — `'kerntaak'` is NOT in the enum. The T3 sibling chose a more refined model: kerntaken are seeded with `programmaStructure: taakveld` (treating kerntaken as a 7-bucket taakveld-flavour rollup) AND introduced a `GLLine.programmaStructure` field carrying the seven kerntaak codes (L7-22 of the T3 fragment) as a parallel programme-allocation field used by the dashboard/linker. The umbrella's REQ-PRB-002 "MUST accept `'kerntaak'`" intent is satisfied through this two-field design — the kerntaak rollup happens via the per-line `programmaStructure` field + `programmeBudgetVsActuals` aggregation in the T3 fragment, not through an enum-value extension on the BBVProgramma discriminator. (f) `ProvincialeFondsPosting` + `opcentenTarief` (on GLLine) + the manifest navigation entries for Provinciale fondsen + `featureFlags.gov-provincie` gate + the ADR-000 annotation are ALL still pending on `development` — these are the four genuine implementation-cycle concerns for which the umbrella's REQ-PRB-004 / REQ-PRB-005 / REQ-PRB-006 hand off to the T3 sibling's implementing PR or to a successor implementing change. The variant-flag + kerntaken seed + kerntaken rollup surface (REQ-PRB-001/002/003) is therefore ALREADY LANDED on `development` via the T3 sibling change, and the four implementation-cycle concerns (ProvincialeFondsPosting + opcentenTarief + manifest + ADR-000) hand off cleanly to the implementing cycle.
