## Decisions

### D1 — The real trigger is `ObjectUpdatedEvent`/`ObjectCreatedEvent`, NOT a lifecycle action or `ObjectTransitionedEvent`

Verified against OpenRegister HEAD:

- `TransitionEngine::transition()`
  (`openregister/lib/Service/Lifecycle/TransitionEngine.php:89-210`) loads
  the object, RBAC-checks `update`, validates `from`→`to`, mutates the field,
  `saveObject`s, and dispatches `ObjectTransitionedEvent`. It reads only
  `to`/`from`/`requires`. **There is no code path that executes an
  `actionParameters` / `actions[]` block** — those blocks in shillinq's
  `register.d` (`StockMoveOffsetCreator::emitOffset`) are descriptive only;
  `emitOffset` has **zero real callers** fleet-wide (confirmed by grep),
  i.e. it is itself an unscanned orphan. A declarative lease "action" would
  be dead on arrival.
- `LeaseContract.x-openregister-lifecycle.transitions` is a **list**
  (`[ {from, to, trigger, guard} ]`), but `TransitionEngine` indexes
  `$transitions[$action]` (map-form). So the `/transition` endpoint throws
  for a lease and **`ObjectTransitionedEvent` is never dispatched** — a
  listener on that event (the `StockMove` pattern) would never fire.
- `MagicMapper::update()`
  (`openregister/lib/Db/MagicMapper.php:8138`) dispatches
  `ObjectUpdatedEvent(newObject, oldObject)` on **every** save through the
  public mutation surface (the path shillinq's generic lease CRUD uses to
  set `status`). `ObjectCreatedEvent` covers a lease seeded/imported already
  `active`.

Decision: add `lib/Listener/LeaseActivationListener.php` listening on
`ObjectUpdatedEvent` **and** `ObjectCreatedEvent`, filtered to schema
`LeaseContract`, that fires `generateSchedule` on the **edge** into `active`
(`ObjectUpdatedEvent`: `old.status !== 'active' && new.status === 'active'`;
`ObjectCreatedEvent`: `status === 'active'`). `generateSchedule` itself
re-guards classification (`IFRS16-capitalised` only) and administration
scope (ADR-005 IDOR), so the listener stays thin. Registered in
`Application::register()` next to `StockMoveTransitionedListener`.

### D2 — Edge detection, not "regenerate on every active save"

`generateSchedule` overwrites rows keyed by `leaseContract` + `periodSequence`
and does **not** check `postedToGl`. Firing it on every save of an active
lease would clobber already-posted schedule rows. The listener therefore
fires **only** on the transition edge into `active`, where the schedule does
not yet exist. Idempotency on that edge is safe (a duplicate activation save
that does not change status is a no-op because `old.status === 'active'`
already).

### D3 — The four `record*` methods are user-driven → a write controller

The remeasurement methods take event-specific inputs that a lifecycle
transition cannot supply — the indexed payment amount, the updated
extension-options array, the modified terms, the recoverable value, plus the
approver and the business trigger description. These are form inputs; the
honest, executing trigger is a `POST` controller, matching how the sibling
gl-tax revival gave `GRIRClearingService::reconcileGRIRSaldoForPeriod` a
`GRIRReconciliationController`.

Decision: add `lib/Controller/LeaseReassessmentController.php` with four
`#[NoAdminRequired]` `POST` endpoints (indexation / extension-option /
modification / impairment). Every endpoint: rejects the anonymous caller
(401), validates `administrationId` via `AdministrationContextService::canAccess`
(cross-tenant masked as 404, ADR-005), validates the lease id slug pattern,
validates the event-specific body, calls the matching `record*` method, and
returns the persisted event payload (201). Four routes in
`appinfo/routes.php` under `leaseReassessment#…`.

### D4 — GL balance is asserted, not merely "it fired"

Each `record*` method already emits balanced `glLines` (catch-up:
Dr RoU / Cr lease-liability for a liability increase, reversed for a
decrease; impairment: Dr `lease-modification-gain-loss` / Cr `rou-asset`).
Every new controller test asserts, on the returned payload, that
`sum(debit amounts) === sum(credit amounts)` **and** the RoU adjustment
equals the liability delta (catch-up) / the impairment magnitude — a posting
that fires but is empty or unbalanced is the same defect in a nicer hat. The
listener test asserts the persisted schedule amortizes: the closing lease
liability of the final period is ~0 and every row's
`interest + principal ≈ payment`.

### D5 — ADR-031: declarative first, exception path only where the DSL cannot express it

- **Declarative** is impossible here: OR's lifecycle DSL has no action
  executor (D1), so the schedule generation and the remeasurement postings
  cannot be expressed declaratively at all. Both need to (a) read the
  `LeaseContract`, (b) run integer-cent IFRS-16 arithmetic via
  `LeaseAmortizationCalculator`, and (c) write multi-row derived objects.
  This is the same exception-path justification `StockMoveTransitionedListener`
  and the gl-tax `FixedAssetDisposalListener` already carry.
- **Exception path**: one event listener (schedule) + one write controller
  (remeasurements). Fail-soft listener (a schedule-write hiccup must not roll
  back the operator's activation, mirroring `StockMoveTransitionedListener`);
  controller returns structured errors without leaking stack traces.
- **Follow-up (out of scope):** `modified→active` partial regeneration and
  auto-regeneration of future schedule periods after an approved
  modification. Filed as a note on #446; not wired here to avoid clobbering
  posted rows without a `postedToGl` guard in `generateSchedule`.

### D6 — Adjacent orphans observed but out of scope (recorded, not silently claimed)

- `LeaseContractGuard::guardActivation` is referenced under the `guard` key
  (not `requires`) with signature `(string, ?array): bool` and does not
  implement `LifecycleGuardInterface`, so `LifecycleValidationListener` never
  runs it — the draft→active completeness check is unenforced. It is a
  **guard**, not a write-capability, so it is outside gate-52 and this
  cluster; noted for a future `register-handler-resolution` sweep.
- `LeaseDisclosureService::exportToXBRL` / `exportToCSV` /
  `exportDisclosureNoteToPDF` are the #446 disclosure-export cluster, not GL
  posting; left untouched.

## Seed data

No new seed files. The IFRS-16 register fragment
(`lib/Settings/register.d/bookkeeping-ifrs-16-lease.json`) already seeds
worked-example `LeaseContract` records (vehicle lease, real-estate lease,
short-term-exempt copier) plus derived schedule and disclosure rows; those
shapes are the fixtures the new tests mirror. The unit tests build their own
in-memory `LeaseContract` fixtures (the proven
`LeasePaymentScheduleServiceTest` stub pattern) so they never depend on a
live register.

## Risks

- **Listener fires on lease saves.** `LeaseActivationListener` runs on every
  `ObjectUpdatedEvent`/`ObjectCreatedEvent`, but returns immediately unless
  the schema is `LeaseContract` **and** the status edge into `active` is
  detected — the same cheap schema+edge guard `StockMoveTransitionedListener`
  and `GLTransactionComplianceCacheListener` use. Fail-soft: any downstream
  error is logged, never bubbled into the activation save.
- **Idempotent regeneration.** Because generation is edge-gated (D2), the
  only re-entry is a duplicate `draft→active` save, which cannot happen
  twice (the first flips `status` to `active`, so the second sees
  `old.status === 'active'` and no-ops).
