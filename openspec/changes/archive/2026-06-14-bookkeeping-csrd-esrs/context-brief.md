# bookkeeping-csrd-esrs

## Purpose

Deliver the data collection, governance, calculation, assurance, and submission backbone for Corporate Sustainability Reporting Directive (CSRD) reporting under the European Sustainability Reporting Standards (ESRS), so that shillinq becomes the practical operating system for the sustainability-reporting wave that hits Dutch MKB+ between 2024 and 2028. CSRD (Directive 2022/2464) entered into force in January 2023 and is being phased in over four reporting cycles: large public-interest entities (FY2024, report 2025), other large companies meeting two-of-three thresholds — 250 employees, EUR 50M turnover, EUR 25M balance-sheet total — (FY2025, report 2026), listed SMEs (FY2026, report 2027, with a possible two-year opt-out to 2028), and non-EU groups with EUR 150M EU turnover (FY2028, report 2029). For the Netherlands, the implementation act amending Titel 9 Boek 2 BW transposed CSRD in late 2024, and the AFM has primary supervisory responsibility for in-scope listed entities while KvK handles deposition. The number of Dutch entities in scope rises from ~150 under the previous NFRD to over 4,500 under CSRD — and shillinq's target tenant base sits squarely in waves 2 and 3.

ESRS is more than a longer non-financial report. It mandates double materiality (an issue is material if it impacts the company *or* the company impacts the issue), demands ~1,100 individual data points across twelve cross-cutting and topical standards, requires limited assurance from year one (rising to reasonable assurance no later than FY2028), enforces a specific digital taxonomy (the EFRAG ESRS XBRL taxonomy, to be tagged in iXBRL alongside the financial statements in the European Single Electronic Format), and explicitly extends the reporting boundary into the value chain — emissions, working conditions, and governance behaviours of suppliers and customers, not only the reporting entity itself. The combination is operationally severe: most in-scope MKB+ companies discover that the data they need (Scope 3 emissions, supplier diversity statistics, water consumption by site, biodiversity-sensitive area overlaps) does not exist in any of their current systems and has to be either freshly collected, modelled with proxies, or sourced from third parties via openconnector.

This change introduces a Sustainability register inside shillinq covering the full ESRS data model, a materiality-assessment workflow (the IRO process — Impacts, Risks, Opportunities), a data-point-driven collection engine that pulls from internal systems and external connectors, a calculation layer for the standard ESRS metrics (most importantly the GHG Protocol Scope 1/2/3 inventory), an assurance workflow for the audit firm, and an XBRL submission pipeline that produces the EFRAG-taxonomy-compliant iXBRL block bundled with the annual report for KvK and (where relevant) AFM deposition. The success criterion is that a shillinq tenant in scope for CSRD wave 2 (FY2025) can complete its first full ESRS report inside the platform — materiality assessment, data collection, calculation, narrative drafting, limited-assurance walkthrough, and XBRL submission — without external consultants beyond the auditor.

## Data Model

The ESRS data model is unusually large. We introduce ten schemas in a new `sustainability` register, plus extensions to existing schemas. The schemas mirror the ESRS architecture (cross-cutting + topical) so that a tenant's reporting set composes naturally as a subset of the model.

**`materiality-assessment`** is the root governance record. Attributes: reporting period, methodology version, assessment scope (legal-entity / consolidated-group), responsible-owner (FK user), stakeholder-groups-consulted (array of {group, consultation-method, date}), threshold-impact (scale 1-5), threshold-financial (scale 1-5), double-materiality-matrix-snapshot (JSON), approval-date, approver (FK user), supporting-documents (files), and superseded-by (self-FK). Every ESRS topical disclosure that is reported (or explicitly omitted) traces back to a row in this record.

**`iro-record`** is the per-topic Impact / Risk / Opportunity entry. Attributes: assessment (FK), ESRS topic code (E1 / E1-1 / E1-2 / S1 / S1-1 / etc.), type (impact-positive / impact-negative / risk / opportunity), description, value-chain location (own-operations / upstream / downstream / financial), time-horizon (short / medium / long), likelihood (1-5), severity-or-magnitude (1-5), scope (1-5), irremediable-character (boolean), gross-or-net (gross-before-mitigation / net-after-mitigation), financial-effect-estimate (currency + range), impact-score (computed), financial-materiality-score (computed), material (boolean — true if either score >= threshold), mitigation-actions (array of {action, owner, due-date}), and rationale (free text).

**`esrs-data-point`** is one row per ESRS-mandated data point per period. ESRS-1 and ESRS-2 alone define ~80 data points; the twelve topical standards together add ~1,000 more. Attributes: period, ESRS data-point ID (e.g., `E1-6_GrossScope1GHGEmissions_tCO2eq`), value (typed: numeric / text / boolean / monetary / quantity), unit (UN/CEFACT code), value-source (manual / openconnector-pull / calculation / imported-from-bookkeeping / supplier-survey / proxy-estimate), source-reference (URI or doc reference), preparer (FK user), preparer-timestamp, reviewer (FK user), reviewer-timestamp, status (draft / in-review / approved / locked-for-assurance / assured), assurance-evidence (files), restated-from (self-FK if a prior-period value was restated), and narrative-comment.

**`ghg-inventory`** is the GHG Protocol calculation engine, called out separately because Scope 1/2/3 is by far the most data-intensive ESRS area. Attributes: period, methodology (GHG-Protocol-Corporate-Standard / GHG-Protocol-Value-Chain-Standard), consolidation-approach (equity-share / financial-control / operational-control), gases-included (array: CO2 / CH4 / N2O / HFCs / PFCs / SF6 / NF3), boundary-narrative, base-year, base-year-recalculation-policy, total-Scope-1, total-Scope-2-location-based, total-Scope-2-market-based, total-Scope-3 (object: 15 categories from purchased goods to investments), intensity-metrics (object: tCO2e per FTE, per turnover, per m2, per unit-produced), and methodology-changes-vs-prior-period.

**`emission-source`** is the per-activity row that feeds the inventory. Attributes: inventory (FK), scope (1 / 2 / 3-cat-N), category (e.g., stationary-combustion / mobile-combustion / fugitive / electricity-purchased / purchased-goods-and-services / capital-goods / fuel-and-energy / upstream-transport / waste / business-travel / employee-commuting / upstream-leased / processing-of-sold / use-of-sold / end-of-life / downstream-leased / franchises / investments), activity-data (numeric), activity-unit, activity-source-document (file or openconnector reference), emission-factor (numeric), emission-factor-source (DEFRA / EPA / IEA / supplier-specific / spend-based-EEIO), emission-factor-version, GWP-version (AR5 / AR6), CO2e-result, uncertainty-rating (high / medium / low), and recalculation-flag.

**`value-chain-actor`** is the supplier / customer / portfolio-company that participates in the reporting boundary. Attributes: counterparty (FK organisations), role (supplier / customer / financial-investee / franchisee), tier (1 / 2 / 3+), country, sector (NACE code), in-scope-for (array of ESRS standard codes), data-collection-method (direct-survey / industry-average / supplier-LCA / regulatory-disclosure), engagement-status (not-contacted / contacted / responded / partial-response / verified), last-engagement-date, and data-quality-score (1-5).

**`esrs-policy`**, **`esrs-action`**, **`esrs-target`**: the standard ESRS-2 governance triad. Policies declare the entity's position on a material topic; actions are the concrete time-bound interventions; targets are the measurable goals (preferably science-based). Each has owner, scope, time-horizon, measurement metric (FK to `esrs-data-point`), baseline-value, target-value, current-value, progress-narrative, and links back to the IRO record(s) that justify it.

**`assurance-engagement`** captures the auditor's work. Attributes: period, audit-firm, lead-partner, engagement-level (limited / reasonable), scope-statement, materiality-threshold-quantitative, materiality-threshold-qualitative, walkthrough-records (files), test-of-controls-results (array), substantive-test-results (array), findings (array of {ESRS-area, severity, description, management-response, status}), assurance-report (file), and opinion-date.

**Extensions:** `journal-entry-line` gets an optional `esrs-data-point` FK so that, for example, every diesel-fuel invoice can directly feed the mobile-combustion emission-source row. `fixed-asset` gets `is-biodiversity-sensitive-area-overlap` (boolean) and `physical-climate-risk-rating` (1-5) for ESRS E1 and E4. `organisations` gets `nace-code`, `country-of-operation`, and the `esrs-in-scope-for` array.

## Requirements

**Double-materiality assessment.** The wizard guides the controller through ESRS-1 §3 by enumerating every potentially-material topic (the ESRS topical-standards taxonomy is pre-loaded as seed data) and asking, for each, two parallel question sets: impact materiality (the company's effect on people and environment, scored on scale × scope × irremediable-character × likelihood) and financial materiality (the topic's expected effect on the company's cash flows, development, financial position, financial performance, access to finance and cost of capital). Stakeholder consultation is captured as evidence; the system enforces at least one consultation method per consulted group. The resulting matrix is signed off, locked, and becomes the source of truth for which ESRS topical standards are in scope for the period. A topic crossing the threshold in either dimension is material; the rationale for every "not material" determination is mandatory and exported in the report.

**ESRS-1 cross-cutting + ESRS-2 general disclosures.** ESRS-1 sets the rules of the game (preparation principles, boundary, value chain, time horizons, materiality, due diligence linkage); ESRS-2 mandates the standard disclosures every entity must make regardless of materiality assessment (basis for preparation, governance, strategy, IRO management, metrics-and-targets framing). The system pre-populates ESRS-1 from tenant master data and ESRS-2 governance disclosures from the tenant's `organisations` register (board composition, committees) and from prior-period values.

**Topical standards E1-E5, S1-S4, G1.** Each topical standard is a configurable module that activates when its materiality determination is positive. **E1 Climate change** covers transition plan, climate-resilience strategy, GHG inventory (the heaviest single workload), Scope 1/2/3 disclosure, internal carbon pricing, EU Taxonomy alignment KPIs, and energy consumption. **E2 Pollution** covers air, water, soil emissions and substances of concern. **E3 Water** covers water consumption, withdrawal, discharge by source and stress-area overlap. **E4 Biodiversity** covers biodiversity-sensitive area overlap (computed from `fixed-asset` location data against the Natura 2000 + Key Biodiversity Areas overlays), species impact, ecosystem services dependence. **E5 Circular economy** covers resource inflows, outflows, waste. **S1 Own workforce** covers headcount breakdowns, pay gap, collective bargaining coverage, health-and-safety incidents, training hours, work-life balance. **S2 Workers in the value chain** mirrors S1 for supply chain. **S3 Affected communities** covers human-rights impacts on adjacent communities. **S4 Consumers and end-users** covers product safety, accessibility, responsible marketing. **G1 Business conduct** covers anti-corruption, lobbying, payment practices to suppliers (the late-payment KPI), whistleblowing channel statistics.

**Data-point collection engine.** Each ESRS data point has a configured source. Internal bookkeeping data flows automatically (e.g., fuel-purchase invoices booked on a specific GL account auto-populate stationary-combustion activity data). External data flows via openconnector adapters: energy-supplier APIs for kWh, fleet-management systems for vehicle data, HRIS for workforce data, supplier-survey platforms (CDP, Worldfavor, Ecovadis) for value-chain data. Manual entry is the fallback with a mandatory source-document attachment. A collection-progress dashboard shows percent-complete by ESRS topic and flags overdue items.

**GHG calculation.** The inventory is computed on demand from the active emission sources for the period using the latest DEFRA / EPA / IEA emission factors (loaded as seed data via openconnector on a quarterly schedule). Both location-based and market-based Scope 2 are produced. Scope 3 uses spend-based EEIO (Exiobase or USEEIO) where supplier-specific data is unavailable, with a clearly-marked data-quality-rating. Base-year recalculation is automatic when a recalculation trigger (≥5% of base-year emissions added/removed via M&A, methodology change, or correction) is reached.

**Audit / assurance workflow.** Once a data point is approved, it can be locked-for-assurance, freezing it from edits but still allowing auditor annotations. The audit firm gets a scoped role with read access plus annotation rights; their findings are tracked through to management response and resolution. Year-one is limited assurance (negative opinion: "nothing came to our attention"); from FY2028 it becomes reasonable assurance (positive opinion). The system supports both engagement levels with the appropriate evidence depth.

**XBRL submission.** Final approved data points and narratives are mapped to the EFRAG ESRS XBRL taxonomy (the digital taxonomy was finalised by EFRAG and the European Commission in 2024 and is updated annually) and emitted as an iXBRL block embedded in the annual-report PDF for ESEF deposition. The submission pipeline reuses bookkeeping-sbr-xbrl-reporting infrastructure and is fully validated against the taxonomy before submission.

**Restatement and audit trail.** Every change to an assured data point in a subsequent period is captured as a restatement with rationale and prior-period comparative. The audit trail is immutable and exportable.

## Standards & Sources

Primary regulation: Directive (EU) 2022/2464 (CSRD) amending the Accounting Directive, the Transparency Directive, the Audit Directive and the Audit Regulation; Commission Delegated Regulation (EU) 2023/2772 adopting the ESRS Set 1 (12 standards: ESRS-1, ESRS-2, E1, E2, E3, E4, E5, S1, S2, S3, S4, G1); Commission Implementing Regulation (forthcoming) on the ESRS XBRL taxonomy; the Dutch implementation act *Wet implementatie richtlijn duurzaamheidsrapportering* (in force Q1 2025). Secondary standards: EFRAG IG-1 *Materiality Assessment Implementation Guidance*, IG-2 *Value Chain Implementation Guidance*, IG-3 *Detailed ESRS Data Point list*; GHG Protocol *Corporate Standard* (revised 2015) and *Corporate Value Chain (Scope 3) Standard*; ISO 14064-1:2018; SBTi *Corporate Net-Zero Standard* for target-setting; EU Taxonomy Regulation (EU) 2020/852 for the E1 climate KPIs that overlap with taxonomy alignment; ISSA 5000 (International Standard on Sustainability Assurance) as the assurance framework adopted by NBA-VRC for Dutch auditors. Practitioner sources: KPMG *ESRS handbook*, PwC *Sustainability reporting under CSRD*, Deloitte iGAAP *Non-financial reporting*, EY *EU Corporate Sustainability Reporting Directive — Q&A*, EFRAG Q&A Platform compiled responses. Emission-factor sources: UK DEFRA conversion factors (annual), US EPA eGRID, IEA emission factors database, IPCC AR5/AR6 GWPs. EEIO sources: Exiobase v3.8 (CML Leiden), USEEIO (US EPA). For biodiversity overlap: WDPA (UNEP-WCMC), Key Biodiversity Areas database, IBAT. For value-chain supplier engagement: CDP supply chain programme, EcoVadis, Worldfavor, Ulula.

## Cross-app integration

**bookkeeping-sbr-xbrl-reporting** is a hard dependency — the ESRS XBRL emission reuses the SBR/XBRL pipeline already built for financial reporting, extended with the EFRAG taxonomy. **openconnector** is a hard dependency — at minimum a dozen external connectors are needed for energy suppliers, fleet systems, HRIS, supplier-survey platforms, government registers (CBS, RVO), and the quarterly emission-factor refresh. **bookkeeping-general-ledger** feeds activity data from invoices via the `journal-entry-line.esrs-data-point` link. **bookkeeping-ifrs-16-lease** feeds the leased-vehicle fleet into mobile-combustion and the leased-buildings into energy consumption. **bookkeeping-fixed-assets-depreciation** provides the asset register that is queried for biodiversity-sensitive-area overlaps and physical-climate-risk ratings. **bookkeeping-ccm-rule-engine** runs controls over the ESRS data flow (e.g., "no ESRS data point may be approved without a source document" is exactly the kind of automated control CCM is built for). **organisations** is the master for the value-chain actor register. **docudesk** stores all evidence (supplier surveys, energy bills, board minutes, policy documents). **decidesk** routes materiality assessments and target-setting decisions through the board governance workflow. **launchpad** publishes the sustainability KPI dashboard (intensity metrics, target progress, collection-progress). **opencatalogi** publishes the CSRD/ESRS capability with the EU regulation and EFRAG standard tags. **openregister** itself, as the platform, gets a sustainability data-quality scorecard since the EFRAG IG-3 data-quality dimensions map naturally onto register-level metadata.

## Target users

The primary user is the **sustainability officer** or **CFO** of a wave-2 CSRD entity (250+ employees, EUR 50M+ turnover) that has just discovered ESRS exists and has nine months to first report. In larger entities the user splits between a **head of sustainability** (owns the report and the materiality assessment), a **CFO** (owns the assurance relationship), a **controller** (owns the data collection), and a **procurement lead** (owns value-chain data collection). Secondary users are the **external auditor** (limited or reasonable assurance), the **board / supervisory board** (signs off the report), and **investor-relations / banking-relationship** staff (who consume the report for ESG disclosures to lenders under SFDR or to banks for the EBA Pillar 3 ESG disclosures). Suppliers are tertiary users when they receive supplier surveys via the value-chain module. For shillinq the strategic value is enormous: CSRD compliance is a EUR 100K–500K consulting project for a typical wave-2 entity; bundling it into the bookkeeping engine that already holds the invoices and asset register makes shillinq the lowest-cost compliant route to ESRS for the entire Dutch MKB+ — a defendable moat for the next decade.
