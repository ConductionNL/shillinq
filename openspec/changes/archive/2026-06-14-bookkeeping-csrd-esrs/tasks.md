# Tasks — Corporate Sustainability Reporting Directive (CSRD) / European Sustainability Reporting Standards (ESRS)

> **Apply cycle (hydra-build).** The declarative core of this `kind: config` change is now implemented: the ten sustainability schemas + the FixedAsset extension ship as the ADR-037 register fragment `lib/Settings/register.d/bookkeeping-csrd-esrs.json` (lifecycle, calculations, aggregations, seed data); the Sustainability frontend ships as the ADR-037 manifest fragment `src/manifest.d/bookkeeping-csrd-esrs.json` (nav + index/detail pages); cross-field lifecycle preconditions ship as `lib/Lifecycle/CsrdEsrsGuard.php` (ADR-031 exception path, real OpenRegister ObjectService API only). Per ADR-031 there are **no** `GHGCalculator`/`ImpactScorer`/`Assurance` PHP services — all quantitative logic is `x-openregister-calculations` / `x-openregister-aggregations`.
>
> **DEFERRED tasks** require a dependency that is **not yet present in shillinq** or a **live instance**, and are marked `[DEFERRED]` inline with a reason. In particular: the `journal-entry-line` and `organisations` schemas referenced by Tasks 11/13 do **not exist** in this app yet (the GL change ships an embedded-`lines` `JournalEntry`, and there is no `organisations`/`contact` schema — a contact/counterparty is a Nextcloud entity, never invented here); the XBRL pipeline (Tasks 30–33), openconnector adapter bridges (Tasks 17, 21, 23), live dashboards/wizards (Tasks 14–19, 24–29) and runtime-verified GL auto-linking (Task 16) depend on `bookkeeping-general-ledger`, `bookkeeping-sbr-xbrl-reporting`, `bookkeeping-ccm-rule-engine`, `organisations`, and `openconnector` being merged, or on a running instance. They are declaratively specified in `specs/bookkeeping-csrd-esrs/index.md` and the schema/lifecycle metadata; their wiring lands when the dependencies do.

### Phase 4: GHG Calculation Engine (weeks 13–18)

## Rollback / Unwind

If spec is rejected post-review, or implementation halted mid-cycle:
- Remove all `sustainability` register schemas from `lib/Settings/shillinq_register.json`
- Revert FK extensions (remove `esrs-data-point` from `journal-entry-line`, `is-biodiversity-sensitive-area-overlap` + `physical-climate-risk-rating` from `fixed-asset`, etc.)
- Remove manifest navigation entries (Materiality Assessment, ESRS Data Points, GHG Inventory, Assurance Engagement)
- Disable openconnector integrations (sustainability-specific adapters)
- Unwind `x-openregister-lifecycle` + `x-openregister-aggregations` rules

**Once any ESRS report is published (status=published, submitted to KvK):** Rollback is not an option. Restatement workflow (next period) is the only path forward.
